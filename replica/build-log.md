## Заметки

- **Сборка.** Здесь собрать APK нельзя: среда не пускает к Google Maven и Gradle. Сборка идёт в GitHub Actions (`.github/workflows/build.yml`). 2026-10-23: сборка зелёная (run 39970485039), debug-APK ≈ 28 МБ (две архитектуры, OpenCV). Проверка «нет INTERNET в манифесте» прошла. На телефоне ещё не проверено.
- **Версии.** AGP 8.7.3, Kotlin 2.1.0, Gradle 8.11.1, Compose BOM 2024.12.01, CameraX 1.4.1, Room 2.6.1. OpenCV взят 4.12.0, а не 4.14 из архитектуры: это проверенная связка со старым AGP. Обновим версии, когда срез соберётся.
- **Алгоритмы.** Сначала проверены на прототипе `proto/pipeline.py` (OpenCV 5.0, Python) на синтетических фото с перекосом, тенью и тёплым светом:
  - углы листа найдены с ошибкой ≤ 5,3 px на кадр 3000 px;
  - после фильтра 99,5 % бумаги ≥ 245;
  - печать осталась красной, подпись синей;
  - на шуме без листа рамка не выдумывается.
  
  Kotlin-код повторяет прототип шаг в шаг. Ради памяти уровни белого считаются по копии до 1000 px, а обработка идёт поканально.
- **PDF.** Тот же алгоритм проверен портом на Python: 50 страниц, строгая проверка pypdf, A4 в нужной ориентации, все смещения xref верны. Размер около 550 КБ на страницу при 300 dpi и JPEG 85 на синтетике — меньше прогноза из архитектуры не получилось, проверим на реальных сканах.
- **Документы из импорта** пропускают S03/S04: лист ищется автоматически, фильтр «Белый фон». Поправить можно тапом по странице.
- **Черновики.** Пустой черновик (камеру открыли и вышли) удаляется при следующем запуске через сутки.

## 2026-10-23, версия 0.2.0 — по первому отзыву с телефона

Отзыв: на светлой скатерти с узором лист не находился, текст не выравнивался по горизонту.
Разбор по присланному PDF:
- детектор принимал за лист рамку кадра: узор рвал контур, а Хаф видел «прямые» сквозь строки текста;
- лист занимал почти весь кадр, края частично за кадром;
- выравнивания строк в срезе не было, страница 1 лежала боком.

Исправлено (прототип → тесты → Kotlin):
- **Поиск листа.** Текст стирается закрытием 11×11. Кандидаты берутся из контуров, масок «бумаги» (V−S) и прямых Хафа. Край кадра — запасная сторона с опорой 0,35. Оценка: опора на края × «бумажность» × √площади. На шуме рамка не выдумывается.
- **Ориентация 0/90/180/270** считается по обрезанному листу: по профилю строк и по выносным элементам над и под строкой. На целом кадре фон сбивает подсказки — проверено.
- **Выпрямление строк** до ±15° выполняется при каждой обработке.
- **Камера** учитывает физический поворот телефона.

Тесты:
- `proto/test_pipeline.py`: 8 случаев, включая 4 на скатерти с узором — углы с точностью 5–13 px на 3000;
- `proto/test_orientation.py`: страница пользователя и латинская синтетика во всех 4 поворотах и с наклоном ±12° — всё верно, угол ±0,2°;
- обе страницы пользователя: обрезка срезает скатерть, страница 1 поворачивается правильно.

CI зелёный (run 39975600194). На телефоне ещё не проверено.

## 2026-10-23, версия 0.3.1 — размер приложения

Вопрос пользователя: почему приложение весит 50 МБ. Разбор debug-APK (51,6 МБ):
- OpenCV arm64 — 24,2 МБ;
- OpenCV armv7 — 16,1 МБ;
- код без R8 — 10,3 МБ;
- прочее — 0,8 МБ.

Сделано:
- release-сборка с R8 и сжатием ресурсов: код 10,3 → 1,6 МБ;
- отдельные APK по архитектурам: arm64 — 26,3 МБ, armv7 для старых телефонов — 18,2 МБ;
- постоянный ключ подписи (`app/skaner.jks`, пароли в `app/signing.properties`; репозиторий приватный). Раньше каждая сборка CI подписывалась новым debug-ключом, и обновить приложение поверх было невозможно.

Осталось: OpenCV — 24,2 из 26,3 МБ. В приложении используются только модули core и imgproc. Своя сборка OpenCV из этих двух модулей должна дать примерно 6–8 МБ на APK — не проверено.

## 2026-10-24, версия 0.7.1 — тень от телефона

Отзыв: рамка встаёт по краю тени от телефона (скриншот экрана границ, книжная страница).
Исходного фото не было — восстановил со скриншота: снял затемнение 50 % вне рамки, закрасил линии и маркеры.
Причины:
- тень синеватая (подсвечена холодным светом при тёплой лампе), и проверка «пёстрости» штрафовала любую рамку, включающую тень: 0,28 против 0,03;
- край тени — длинная прямая, идущая по тексту.

Сделано:
- пёстрость не учитывает пиксели темнее 85 % медианной яркости с тоном 95–135 — синеватую тень; скатерть остаётся пёстрой при любой яркости;
- `text_crossing_sides`: если по обе стороны стороны есть текст и профили штрихов вдоль неё совпадают (корреляция > 0,4), это край тени, штраф ×0,1. На всех настоящих краях корреляция ≤ 0,03, на крае тени — 0,79;
- `inner_edge_sides`: сильный прямой край внутри рамки параллельно стороне, на 3–25 % её размера, — корешок или соседний лист, штраф ×0,6. Тонкие напечатанные линии исключены по карте штрихов.

Проверено:
- `proto/test_real.py`: книга — рамка по корешку, ошибка 0 px; полис и ЭКГ без изменений;
- синтетика 8/8, просвет, ориентация — OK.

CI зелёный, релиз v0.7.1.
